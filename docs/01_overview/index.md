# 保険金請求・査定前後の実務 / 01_overview

    ## ビジョン
    保険金支払いを、保険会社都合の手作業ではなく、契約者視点の迅速で説明可能な運用へ変える。

    ## このドメインをどう見るか
    この領域の本質は、**書類やフォームを処理すること**ではない。  
    本質は、**意思決定に必要な正当性・証拠・ルール適合性・責任所在を、期限内に接続すること**である。

    したがって本テーマは、単なる自動化ツールではなく、次の問いに答える業務基盤として捉える。

    - いま何の案件が動いているか
    - その案件はどの規則・契約・証拠に拘束されるか
    - 次に誰が何をすべきか
    - 何が例外で、何が通常か
    - 顧客価値は「処理件数」ではなく、どの結果改善で測るべきか

    ## 対象ドメイン
    事故受付から支払判断までの間に、必要書類案内、損害情報整理、補足照会、支払根拠説明、異議対応が分断され、コールセンター・査定・BPO に重いオペレーション負荷がかかる。

    ## 顧客と受益者
    - **一次顧客（予算保持者）**: 損害保険会社、医療保険・旅行保険事業者、TPA、保険BPO、医療請求/denial管理事業者
    - **現場受益者**: 業務担当者、管理者、監査/統制担当
    - **最終受益者**: エンドユーザー、患者、取引先、契約者、発注者など、処理遅延や品質ばらつきの影響を受ける当事者

    ## 顧客が利益を被るメカニズム
    初動受付時間短縮、追加資料往復削減、査定前の論点明確化、支払説明品質向上、異議/再審査処理の高速化

    重要なのは、「1人の作業を軽くする」だけで終わらないことだ。  
    このドメインでは、遅延や不整合が **売上、資金化、顧客体験、規制対応、監査対応** に波及する。  
    だからこそ、プロダクトの価値は UI の便利さではなく、**業務のボトルネックを外せるか** で決まる。

    ## なぜ10億円級が狙えるか
    保険・請求処理ソフトウェア市場は複数調査で大きく成長しており、Technavio は 2025-2029 年で 271.9億ドルの成長を見込む。Reuters は Allianz Partners が AI 活用により旅行保険部門で 1,500〜1,800人の削減を検討していると報じており、Claims オペレーションは人海戦術の置換対象になっている。[R1][R2]

    ## 主要アクター
    - **契約者/被保険者**: 事故申告・証憑提出
- **FNOL担当**: 初回事故受付
- **査定担当**: 支払可否・金額判断
- **提携事業者**: 修理工場・医療機関・調査会社
- **異議処理担当**: 再審査・苦情対応

    ## 提供するべきプロダクトの姿
    この領域では、チャットUIや文書要約だけでは不十分である。必要なのは以下を備えた「業務OS」である。

    1. 案件・ケースの集約
    2. ルールと証拠の接続
    3. 例外の検知と優先順位付け
    4. 関係者へのアサインと追跡
    5. 監査証跡と再現性
    6. 学習ループ（過去案件を次回運用へ還元）

    ## 本資料におけるプロダクト方針
    - ドメイン用語を先に定義し、実装詳細は後ろに置く
    - 生成AIは一部機能であり、中心はケース運用と状態管理
    - 既存基幹システムを置き換えるより、**既存システム間の高摩擦部分を支配する**
